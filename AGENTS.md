# Apple Shortcut generator

When asked to create a shortcut from ordinary language, act as the planner and complete the build. Do not ask the user to copy JSON or inspect CI logs.

1. Install `shortcutkit` (and `openai` if planning through the API). Use `python scripts/generate_action_database.py --search '<terms>'` for candidate actions and inspect `shortcutkit.get_action(identifier)` for exact keys, kinds, enum choices, input and output metadata. The catalogue is generated from WorkflowKit/ActionKit and Apple's App Intents index; do not invent identifiers or parameters.
2. Produce a semantic JSON blueprint: `{"actions":[{"action":"Ask for Input","id":"answer","parameters":{"Input Type":"Text","question":"Enter text"}}, {"action":"Show Notification","parameters":{"Body":{"$text":["Entered: ",{"$ref":"answer"}]}}}]}`. A parameter may be specified by an exact key or an unambiguous metadata label. `{"$ref":"id"}` references an earlier action; `{"$variable":"name"}` references a named variable set earlier by Set Variable; `$text` embeds references.
3. Structure control flow with `{"if":{"input":{"$ref":"id"},"condition":"contains","value":"work"},"then":[...],"else":[...]}`, `{"repeat":{"count":3},"actions":[...]}`, `{"repeat":{"items":{"$ref":"id"}},"actions":[...]}`, or `{"menu":{"prompt":"Pick","options":{"A":[...],"B":[...]}}}`. Use ordinary List `Items` arrays and Dictionary `Items` mappings for simple text, number and boolean values. For exotic encodings, require a source sample or an explicit vetted serialization; fail rather than guess.
4. Run `python scripts/build_shortcut.py 'Name' '<JSON blueprint>'`. It validates identifier, parameter kinds, action references, and control-flow grouping before HubSign. Inspect the unsigned plist, action count, and errors; fix and repeat. Run `python -m unittest discover -s tests -v`.
5. Return the signed file only after a structural check. Tell the user that import and runtime behavior still require iPhone testing. App Intents require the corresponding app installed on the device; third-party intents require imported metadata and are not assumed available.

Plain language passed directly to the script uses `scripts/plan_with_ai.py` and requires `OPENAI_API_KEY`. An AI coding agent can plan with the catalogue without that API key. GitHub Actions uses the `OPENAI_API_KEY` repository secret for plain-language dispatches. The push workflow uses a deterministic integration blueprint to test construction and signing without paid inference.
